# Contrato entre etapas

Guardar contexto en el área documental/de prototipos existente; si no existe, usar `docs/visual-refresh/<vista>/`. No convertir documentos en código activo ni guardar datos reales de clientes.

## Descubrimiento

Crear `brief.md` con vista, rutas, usuario, tareas, perfil justificado; tokens efectivos y sus fuentes; matriz acción → condición/permiso → ruta/efecto → comportamiento a conservar; problemas con evidencia; dos direcciones cuando se explore, recomendación y decisiones; skills realmente leídas/ejecutadas y limitaciones.

Crear prototipo aislado navegable, con escritorio, móvil y estados representativos. Documentar apertura, interacciones reales y simuladas. Un texto no sustituye la propuesta visual. Si no se puede abrir navegador, entregar HTML local o artefacto visual disponible sin afirmar verificación de navegador.

## Elección e implementación

Registrar dirección, alcance y autorización de la sesión en `decision.md`; no inventar aprobación ni exigir al usuario ese archivo. Reutilizar autorización del chat cuando exista.

Implementar conservando contrato funcional y estilos efectivos. Crear `verification.md` con comprobación → viewport/tema/entorno → ejecutada o pendiente → resultado → evidencia. Un checklist pendiente no demuestra validación.

## Respaldo si falta una skill de la suite

1. Confirmar vista por código; leer estilos, instrucciones y componentes.
2. Leer recursos externos disponibles; registrar ausencias.
3. Auditar tareas: operación y estados en SaaS; descubrimiento y compra en ecommerce.
4. Crear brief y prototipo aislado; usar autorización existente para decidir si continuar o presentar elección.
5. Implementar el alcance elegido con tokens compatibles y comportamiento intacto; comprobar tamaños, temas, estados y checks pertinentes. Comunicar evidencia y pendientes.
