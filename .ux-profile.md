# UX Profile

Generated by `setup-ui-ux-skills`. All UI/UX skills in this project read this file before changing layout, copy, or interaction.

## Aesthetic reference

- **Standard:** Custom (GELIA)
- **Notes:** La referencia es la identidad propia de GELIA, descrita en `GUIA_DISENO_GELIA.md` y `PRODUCT.md`. Se parte de los tokens (`resources/css/gelia/`), las primitivas y los componentes existentes, y se conservan tema, fuente y acento personalizables. Las skills aportan técnica; no deciden la personalidad del producto. Las decisiones explícitas más recientes del usuario prevalecen sobre este perfil.

## Banned anti-aesthetics

- Glassmorphism o `backdrop-filter` sin un borde de alto contraste. Los paneles usan superficie sólida.
- Pastillas pastel flotantes para metadatos ordinarios. Los badges se reservan para estados operativos reales (pendiente, en custodia, entregado).
- Degradados decorativos arbitrarios. El borde neón se permite como acento puntual, con contraste suficiente y una razón funcional.
- Degradados arcoíris en los CTA estándar.
- Ilustraciones de caricatura en los estados vacíos.
- Scrollbars anidados y exceso de iconos dentro de los inputs.
- Códigos de ficha de proceso (T-01, T-02…) en botones, avisos o movimientos de usuario. Se usan nombres de operación.
- Cambiar la estética por defecto de una skill sin una necesidad concreta.
- Pantallas de demostración que el encargo no pidió.

## Accessibility target

- **Level:** WCAG 2.1 AA
- **Contrast:** Más de 4.5:1 en texto normal; 3:1 en texto grande y bordes. Debe cumplirse con el tema y el acento personalizados.
- **Touch / focus:** Objetivos táctiles de 44×44 px y anillos de foco refinados y visibles.

## Brand tone and microcopy voice

- **Voice:** Utilitarian & Minimal
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:** Español, preciso y directo. Los botones empiezan con un verbo y usan nombres de operación («Cerrar consulta», «Confirmar estado»), nunca códigos de ficha. El tono es formal sin perder carácter.

## Icon library

- **Library:** Lucide
- **Package / path:** `lucide-react` (`package.json`); iconos usados en `resources/js/`
- **Notes:** Una sola librería para la interfaz de producto. Se permiten variantes animadas de Lucide (lucide-animated.com) cuando apliquen: acción principal de una vista, cambio de estado confirmado, estados vacíos y otros momentos con una razón concreta. No van en tablas densas, filas repetidas ni toolbars de uso continuo. El movimiento es corto, solo en hover, foco o cambio de estado, sin bucles, y cae a icono estático con `prefers-reduced-motion`. No se reemplazan masivamente los iconos existentes: se adoptan al tocar cada pantalla. La dependencia `motion` se añade con el primer caso real, no durante el setup. Sin emojis como iconos de interfaz.

## Agent rules

1. Read this profile before creating or editing any UI, CSS, or microcopy.
2. Prefer skills by task: new page → `page-patterns` (name the pattern before markup); layout / chrome → `viewports`; forms → `forms`; overlays → `surfaces`; loaders → `loaders`; empty views → `empty-states`; motion → `motion`. Before finishing UI, run `ux-audit`.
3. Use only the recorded icon library (or project SVG path). Do not mix icon sets or use emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation dialog.
